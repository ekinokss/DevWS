## 2. Packaging decision

Self-contained WPF folder deployment, Windows x64, installed under:

```text
%LOCALAPPDATA%\<product install root>\
  app\
    ws.ps1
    lib\...
    editor\
      DevWS.Editor.exe
      [self-contained .NET/WPF files]
      ws-editor-backend.ps1
      editor-projection.ps1
      editor-payload.json
```

The production editor project remains `net8.0-windows`, `win-x64`. The publish is a folder
(`PublishSingleFile=false`) with `--self-contained true`; installed users do not need the
.NET Desktop Runtime. No third-party package was added.

The backend resolves `app\lib` from its adjacent installed location; it does not depend on a
repository checkout or a .NET SDK.

## 3. Package construction and provenance

`packaging/build-editor-payload.ps1`:

1. Resolves the committed source SHA.
2. Runs `git archive` for the lifecycle scripts, `src`, and `config`.
3. Publishes the production WPF project self-contained for `win-x64`.
4. Copies `ws-editor-backend.ps1` and `editor-projection.ps1` beside the executable.
5. Rejects PDB/debug, source, project, XAML, `bin`, `obj`, test, and documentation content.
6. Requires the executable, DLL, deps/runtime config, WPF framework assemblies, backend,
   projection, and payload manifest.
7. Generates `editor-payload.json` with the source SHA, SDK, WindowsDesktop runtime, and a
   deterministic path/size/SHA-256 inventory.
8. Adds the editor files to the existing payload zip under `editor/`.
9. Verifies the resulting archive before the bootstrapper embeds it.

`packaging/build-setup.ps1` uses this builder for production payloads and validates the
editor entries before Native AOT publishing. Fixture packaging can require the editor with
`-RequireEditor`.

## 4. Installer manifest and staging

`Get-DevWSInstallManifest` now includes `app\editor\*` entries when the payload supplies an
`editor` directory. The source-mode repository has no such directory, so source-mode installs
remain valid without an editor payload and without a .NET SDK requirement.

The editor-specific installer path:

1. Refuses to stage while a managed installed `DevWS.Editor.exe` process is running.
2. Validates `editor-payload.json` and every source file's size/hash before any target change.
3. Copies the complete payload into `app\.editor-staging-<guid>`.
4. Re-validates the staged copy.
5. Moves an existing `app\editor` to a temporary backup, promotes the staging directory, and
   restores the backup if promotion fails.
6. Removes the backup and staging debris only after success.

Missing/corrupt dependencies are detected by `Get-DevWSMissingInstalledFiles` using the
manifest hashes. Same-version reinstall repairs both missing and corrupted editor files.
Health check `editor-payload` verifies the installed manifest and hashes; source-mode installs
without an editor directory pass that check.

The bootstrapper passes the embedded product's install-root leaf to the installer and
uninstaller through `DEVWS_INSTALL_ROOT`, so fixture products use their own root. Production
identity remains `%LOCALAPPDATA%\DevWS`.

## 5. Uninstall and repair

Uninstall plan removes the entire validated `app` directory, including `app\editor`. Before
any removal, `Invoke-DevWSUninstall` checks for a running `DevWS.Editor.exe` whose executable
path is under the managed `app\editor` directory. If present, uninstall refuses with a clear
recoverable error; it does not kill arbitrary processes. Default uninstall preserves the
canonical configuration and user data.

Bootstrapper fixture lifecycle tests preserve their existing behaviour: fresh install,
same-version reinstall, upgrade, downgrade refusal, controlled failure preservation, protected
ARP/SID setup state, uninstall self-removal, and user-data preservation all pass.

## 6. Installed launch and security design

- Editor manifest remains `asInvoker`.
- Normal desktop launch is expected at Medium integrity; the editor refuses High integrity.
- The backend is started with the absolute trusted `pwsh.exe` resolved by `PwshLocator`.
- No PATH-based fallback outside the protected Program Files/WindowsApps roots is used.
- Installed mode does not accept development path overrides; `--dev-config` retains the
  visible development badge and separate semantics.
- The editor does not start a worker, broker, coordinator, listener, service, task, or daemon.
- The elevated bootstrapper never launches the editor.

No Start Menu shortcut was added. The documented launch path is the installed absolute
executable:

```text
%LOCALAPPDATA%\<install root>\app\editor\DevWS.Editor.exe
```
