## 7. P9-BR correction — window measurement, shim, final verdict (2026-11-07)

### 7.1 Window measurement reconciliation

The Gate B archive was retrieved from
`gdrive:devws/acceptance/p9b-2026-11-07/gate-b-d1/p9b-2026-11-07-d1-evidence.zip` and its
SHA-256 was re-verified as
`def52584f535dcc88507faadf897a0b267ca24b4423bf789dd13f8705b296236` before use.

Archived measurement fields:

- `d1-positive.json` → `window`: title, PID, `rect {x,y,w,h}`, integrity. No API field.
- `d1-skip2.json` → `windows`: `title|pid|x,y,WxH`. No API field.
- `d1-evidence.json` → same shape for the first launch.

The measurement routine attempted `DwmGetWindowAttribute(DWMWA_EXTENDED_FRAME_BOUNDS)` first
and fell back to `GetWindowRect`, but the persisted records do not say which call produced
the value. **The archive therefore does not contain a recorded Win32 `GetWindowRect`
observation**, and the ±1 px outer-rectangle criterion is unresolved.

Documented semantics: on Windows 10/11, resizable windows carry invisible resize borders
(typically 7–8 px on the left, right and bottom) that are included by `GetWindowRect` but
excluded by `DWMWA_EXTENDED_FRAME_BOUNDS`. The positive values are exactly consistent with
that:

| Frame | Left | Top | Width | Height |
| --- | --- | --- | --- | --- |
| Requested / expected outer | 512 | 360 | 512 | 360 |
| Recorded (DWM extended frame) | 519 | 360 | 498 | 353 |
| Difference | +7 | 0 | −14 | −7 |

That is a 7 px inset on left/right/bottom, i.e. the DWM visible frame of an outer rectangle
equal to the requested one. This is an **inference from documented DWM semantics, not an
observed `GetWindowRect` measurement**, and it is not claimed as one.

Correction to the original wording: the positive size difference is **not** Windows
Terminal character-cell snapping. Character/minimum-size adjustment is visible in the
fallback case instead: recorded DWM `207,200 466x233` implies an outer rectangle of
`200,200 480x240`, where height matches the requested 240 but width is expanded from 320 to
480 (Terminal minimum width). The skip case's recorded `77,78 1030x628` implies an outer
default near `70,78 1044x635`.

### 7.2 `ws.cmd` root cause and correction

Original shim:

```bat
@echo off
pwsh.exe -NoLogo -NoProfile -File "%LOCALAPPDATA%\DevWS\app\ws.ps1" %*
```

Two distinct defects:

1. **Inherited delayed expansion.** Under `cmd /v:on`, `!` in an argument is expanded while
   the shim runs; `a!b` arrived as `ab`.
2. **Unquoted `cmd.exe` metacharacters.** `&`, `|`, `<`, `>` and `^` are parsed by
   `cmd.exe` before any batch file starts. The P9-B driver passed the `path:` identity
   unquoted, so only `path:MSH062E/5` reached the shim and the remainder was interpreted as
   commands. Quoted arguments were already preserved by `%*`, but the requirement was
   undocumented and the boundary/exit contract was implicit.

Corrected shim (PR #14, `fix/v0.3-ws-shim-argument-forwarding`):

```bat
@echo off
setlocal EnableExtensions DisableDelayedExpansion
pwsh.exe -NoLogo -NoProfile -File "%LOCALAPPDATA%\DevWS\app\ws.ps1" %*
exit /b %ERRORLEVEL%
```

The caller's `%*` is forwarded unchanged (no second-stage re-quoting), delayed expansion is
disabled, the install path remains quoted, and the CLI exit code is returned explicitly. The
forwarding-shim recognizer accepts both the pre-fix two-line form and the new form.

Regression tests execute the actual `src\shim\ws.cmd` through `cmd.exe`, with a redirected
`%LOCALAPPDATA%`, a spaced test root, and a stub `ws.ps1` that records argv and exit codes.
Covered: quoted `path:` identity containing `&`; spaces; `|`, `^`, `%`; `!` under
caller-enabled delayed expansion; quoted `& echo ... > file` not executing; exit-code
propagation; and the explicit documented case that an unquoted `&` is split before the shim.

Full canonical suite: **911/911 passed** (0 failed, 0 skipped). Focused
`install-layout,legacy-shim,source-hygiene`: 27/27.

Limits: a `.cmd` shim cannot recover unquoted `&`/`|`/`<`/`>`; full transparency would need
a native entry point, which is out of scope. The installed shim was not re-executed inside a
guest after the fix, and unquoted metacharacters still require the caller to quote.
