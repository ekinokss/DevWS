**N2 correction — why "no window was created" is withdrawn.**

The earlier claim was: *"launch exit 1; no window created (`windowCount=0`) — skipped as
designed."* The exit code and the empty inventory are real, but the inference from them is not
supported. Two independent facts contradict it:

1. **The launch output says the windows were created.** The recorded text is
   `ws: Terminal 'e2-missing' in set 'main': was created but could not be identified. | Terminal 'e2-skip' in set 'main': was created but could not be identified.`
2. **The source confirms creation is not suppressed.** In `devws-lifecycle-layout.ps1`, an
   unreachable fallback sets `ApplyGeometry = $false` and emits the warning *"the item will be
   handled normally but its window position will not be changed."* In
   `devws-terminal-launch.ps1` the plan record for a non-present terminal is built in the
   `State = "missing"` branch together with its `CreateArguments`; `ApplyGeometry=$false` only
   suppresses the later *move*. A skipped placement therefore still launches a window — it just
   is not positioned.

So `windowCount = 0` most plausibly means the measuring harness **failed to enumerate** the
window (the same run had already printed "could not be identified"), not that no window
existed. Supporting that reading: the N2 `launchText` lists **two** unidentifiable terminals
(`e2-missing` and `e2-skip`), because the N2 phase ran with the three-item config still
present — the `show-layout` output captured in the same evidence block lists all three items
(`e2-item`, `e2-missing`, `e2-skip`).

Additional gaps that prevent a clean refusal from being established from existing evidence:

- No `DEVWS_LAUNCH_TRACE` was captured for the N2 run, so there is no `lifecycle-layout-plan`
  record showing the skip decision, and no `stage2-*` sequence for it.
- The N2 host state was contaminated: the `e2-missing` item from N1 was still in the set, so
  the run was not a single-item unreachable-fallback test.
- The window inventory was a title-prefix enumeration performed by the harness; it is not a
  whole-desktop oracle and returned nothing even though the CLI reported creation.

**N2 is therefore recorded as INCONCLUSIVE.** This is *not* a product-defect claim: the
diagnostic evidence is insufficient to say whether the refusal semantics are correct, wrong, or
merely unobserved. Establishing it would need a clean single-item run with the trace enabled
and an inventory that does not depend on window titles — work outside this offline
reconciliation pass.

**D2 installed lifecycle is NOT QUALIFIED.** The positive placement result is strong and
stands on its own: the installed CLI authored a relative record, the elevated broker placed a
real managed window at `-1280,341 1280x696`, and two independent APIs measured it at **zero
error** against the resolved rectangle. That is the core of the layer.

It is not sufficient for the full verdict because two required acceptance criteria are not
satisfied on the existing evidence:

1. **Unreachable-fallback refusal is INCONCLUSIVE (N2).** The archive cannot show that the
   skipped placement produced no window, and the source shows a skipped placement still
   creates its window without positioning it. The earlier "no window created" claim is
   withdrawn.
2. **Exact DevWS token stability across reconnect is NOT FULLY EVIDENCED.** Only one DevWS
   token capture exists and it is post-reconnect. The underlying Windows device instance was
   stable, but that is an inference, not a recorded DevWS measurement.

Scoping notes that belong with the verdict:

1. This work is **RDP-session** based, not physical-hardware based. The negative origin was
   produced by the remote terminal's indirect display driver mirroring the client's monitor
   arrangement — the mechanism P9-D hypothesised. D2's physical-hardware editor layer was
   qualified separately in P9-C; installed-lifecycle placement on physical panels remains
   unqualified.
2. The two guest monitors share one adapter class and are distinguished only by device
   instance. That is enough for distinct identity here, but it is a narrower identity margin
   than two physically distinct panels.
3. **Screenshots — scoped exception accepted.** API-based geometry evidence (`GetWindowRect`
   with explicit provenance, plus DWM bounds recorded separately) is accepted **for the
   placement measurement only**, in place of pixel screenshots that this RDP session could not
   produce. This exception does not extend to any other criterion, and it does not upgrade
   E1/N2.

D3–D6 are untouched by this pass.
