## 2. Architecture

The integrated application is a .NET 8 WPF editor with no third-party packages.

```text
DevWS.Editor.exe (Medium, asInvoker)
  ├─ read-only view model + canvas
  └─ persistent ws-editor-backend.ps1 child (Medium)
       ├─ hello / inspect / read-config / project / shutdown
       └─ existing DevWS resolver libraries (read-only)
```

| Component | Responsibility |
| --- | --- |
| `src/editor/gui/App.xaml(.cs)` | Startup, integrity gate, development-mode flag, smoke mode. |
| `src/editor/gui/MainWindow.xaml(.cs)` | Set/monitor/item lists, read-only details, warnings, canvas interaction, refresh. |
| `src/editor/gui/BackendClient.cs` | Trusted child launch, UTF-8 JSON Lines transport, correlation, timeouts, restart, stderr handling, shutdown. |
| `src/editor/gui/EditorSession.cs` | `hello → inspect → read-config → project` sequence and revision/topology consistency checks. |
| `src/editor/gui/EditorModels.cs` | Typed read-only protocol/projection model. |
| `src/editor/gui/EditorViewModel.cs` | Set selection, projection application, item/monitor selection, read-only detail rows, warnings, recoverable error state. |
| `src/editor/gui/CanvasTransform.cs` | Backend virtual-screen coordinates ↔ drawing coordinates; no DPI geometry. |
| `src/editor/gui/WorkspaceCanvas.cs` | Monitor bounds, work areas, effective item rectangles, selection, zoom, pan, fit, warning markers. |
| `src/editor/gui/IntegrityProbe.cs` | Token integrity-level query. |

The canvas uses:

```text
canvasPoint = (backendPoint - virtualScreenOrigin) * zoom + pan
backendPoint = (canvasPoint - pan) / zoom + virtualScreenOrigin
```

Coordinates are taken from the backend topology/projection. The GUI does not call
`System.Windows.Forms.Screen`, `GetSystemMetrics`, `GetWindowRect`, or `GetDpiForMonitor`.
Negative origins and negative item coordinates are preserved by subtraction, not clamping.

## 3. Supported operations and interactions

The editor advertises and uses only the P3 read-only operations:

- `hello`
- `inspect`
- `read-config`
- `project`
- `shutdown`

`save`, `validate`, `preview`, and `convert` are never called by production GUI code. The UI
has no Apply, Save, Launch, Focus, or live Reset button. “Reset view” only resets the canvas
zoom/pan.

Interactions:

- Workspace-set list, with the default set marked; selecting a set loads its projection.
- Monitor list and canvas monitor selection.
- Configured-item list and canvas item selection.
- Read-only item details: ID, type, enabled state, layout mode, effective rectangle,
  placement source/status, set profile match, item profile entry, relative anchor/status,
  relative rectangle/reachability, fallback rectangle/used/reachable, reachability, visible
  ratio, apply-geometry state, and warnings.
- Projection warnings list, plus warnings relevant to the selected item.
- Zoom in/out, fit-to-view, reset view, mouse-wheel zoom, middle/right-drag pan, and
  arrow-key pan when the canvas has focus.
- Refresh reruns the complete loading sequence.
- Development-config badge, configuration source, revision, backend PID, integrity, zoom,
  pointer coordinates, and counts in the status bar.

## 4. Backend client and loading

`BackendClient` launches an absolute, validated `pwsh.exe` with:

```text
-NoLogo -NoProfile -NonInteractive -File <absolute ws-editor-backend.ps1>
```

It never uses `-Command`, `Invoke-Expression`, a user-writable PATH lookup, a named pipe, a
socket, an HTTP listener, or a background service. One persistent child is kept per editor
window. Requests are serialized, IDs are unique, and every response is checked for protocol,
ID, operation, and result shape.

PowerShell resolution accepts only:

- `%ProgramFiles%\PowerShell\7\pwsh.exe` / `7-preview`;
- a `pwsh.exe` under `%ProgramFiles%\PowerShell\<version>`;
- a validated `%ProgramFiles%\WindowsApps\Microsoft.PowerShell_*_x64__8wekyb3d8bbwe\pwsh.exe`
  path derived from trusted Program Files package metadata.

The backend script is resolved from the installed same-folder layout or, for the repository
build, by walking up to `src/editor/ws-editor-backend.ps1`.

The normal installed-mode child environment removes `DEVWS_CONFIG`, `DEVWS_STATE_ROOT`, and
`DEVWS_INSTALL_ROOT`. An explicit development mode (`--dev-config <path>`) is the only
override; it is visibly marked “DEVELOPMENT CONFIG” and still cannot expose an arbitrary
`configPath` protocol field.

Loading is strictly:

```text
hello → inspect → read-config → project
```

The editor checks `read-config.sha256 == inspect.config.sha256 == project.configRevision`
and compares the inspect/project topology fingerprints. A mismatch discards the inconsistent
projection and requires Refresh. `read-config` receives the exact hash from `inspect`.
Read-only transport failures may restart the child and retry once; structured backend errors
are surfaced with their code/message/details; malformed responses are protocol errors and are
not treated as results.

## 5. Integrity and security

- The executable manifest is `asInvoker` with PerMonitorV2 DPI awareness.
- Startup refuses High/System integrity with a clear “must run at normal (Medium) integrity”
  message.
- All positive GUI smokes reported `Integrity: Medium`.
- The backend child inherits the same normal-integrity token.
- No worker, broker, coordinator, scheduled task, privileged process, pipe, socket, listener,
  or live-window operation is used.
- Production GUI source is covered by a deterministic boundary test that rejects privileged
  or live-window symbols and rejects calls to `save`/`validate`/`preview`/`convert`.

The high-integrity probe displayed:

```text
DevWS Editor must run at normal (Medium) integrity. The current process is High.

Close this elevated instance and launch the editor normally. Configuration editing is a
normal-integrity operation.
```

The modal was terminated by the test harness after the refusal message was captured; the
positive Medium-integrity runs are the execution evidence.

## 9. Build and launch

Requires the .NET 8 SDK and Windows Desktop runtime.

```powershell
dotnet build .\src\editor\gui\DevWS.Editor.csproj -c Release
.\src\editor\gui\bin\Release\net8.0-windows\win-x64\DevWS.Editor.exe
```

Launch normally from the interactive desktop. Do **not** run it elevated; the editor refuses
non-Medium integrity.

Development configuration:

```powershell
.\src\editor\gui\bin\Release\net8.0-windows\win-x64\DevWS.Editor.exe `
  --dev-config "C:\path\to\workspace.json"
```

## 11. Limitations and unexecuted cases

- **Mixed-DPI physical behavior: NOT EXECUTED.** The host has two 100% monitors.
- **Negative physical monitor origin: NOT EXECUTED.** Negative origins are synthetic; the
  real canonical config supplied a negative item X, not a negative monitor origin.
- **Physical EDID identity, primary-monitor change, disconnect/reconnect: NOT QUALIFIED.**
- **Installed-product integration: NOT EXECUTED.** P4 runs the repository build; it does not
  rebuild the installer or install shortcuts.
- **No geometry editing, validate, preview, convert, warning acknowledgement, or save.**
- **No live-window launch/focus/reset.**
- **Custom canvas per-shape automation peers: not implemented.** Lists/details are the
  keyboard alternative.
- **200-item integrated performance is heavier.** The synthetic 200-item smoke loaded in
  about 8.1 s and refreshed in about 4.9 s (medians), versus about 2.0 s / 0.25 s for the
  5-item synthetic smoke. This is a stress observation, not a production performance claim;
  virtualization/rendering optimization is future work.
- **Cold-start and mixed-DPI rendering are not claimed.** The measurements are warm-build
  launches on the P4 host.
