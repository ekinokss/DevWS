# DevWS v0.4.0 Release Readiness

**Status: published as an unsigned GitHub pre-release.** `v0.4.0` is tagged and published at
https://github.com/ekinokss/DevWS/releases/tag/v0.4.0, built from the merged `main` commit
`9dea27776e4fa1896506ad1ea733eab0791ba5a3`. No v0.4.0 WinGet manifest exists. `v0.2.0` remains
the latest stable release and `v0.3.0` remains an existing pre-release.

This document is the durable readiness record for the v0.4.0 release decision. It separates
what was actually executed and retained as evidence from what was measured without supporting
the intended conclusion, and from what was never fully exercised. It deliberately does **not**
collapse distinct environments into a single verdict.

Recording date: 2026-11-15. Prepared on branch `release/v0.4.0-rc-preparation` from
`81b8ab4d0dab461d8b9e5287a41bad8e219e3b8f`.

## 1. Verdict vocabulary

These terms are used with fixed meaning throughout this document.

| Term | Meaning |
| --- | --- |
| **PASS** | Executed, and the retained evidence substantiates the stated conclusion within the stated scope. |
| **INCONCLUSIVE** | Executed and measured, but the retained evidence cannot substantiate the intended conclusion. Not a defect claim. |
| **NOT QUALIFIED / NOT TESTED** | Not fully exercised, or exercised only in an environment that cannot support the claim. No conclusion is drawn. |

A PASS is always scoped. "PASS" never means "correct in every environment"; the scope column
is part of the verdict, not a caveat appended to it.

## 3. Outstanding release gates

### 3.1 Potential release blockers

These should be resolved or explicitly and narrowly disclosed before v0.4.0 is published.

- **R-08 / R-09 / R-10 / R-11 — physical display scenarios.** v0.4.0's headline feature is
  display geometry authoring, and the qualified multi-monitor evidence is RDP-guest-only. A
  release that markets multi-monitor authoring while physical-panel, mixed-DPI and
  primary-change behavior are unqualified must state that limitation prominently.

### 3.1b Previously identified blockers now closed

- **R-18 — source-to-packaged upgrade** was the highest-priority gate in earlier revisions of
  this document. It closed in **P10-A2**: a frozen v0.3.0 source installation was upgraded to
  the packaged v0.4.0 candidate in a disposable guest, with byte-identical configuration
  preservation and the editor installed and launched at Medium integrity.
- **Packaged-to-packaged upgrade and package-identity handling** closed in **P10-A3**
  (R-19/R-20): the published v0.3.0 package was authenticated by hash, installed, and then
  upgraded by the v0.4.0 candidate, which correctly reported `upgrade from 0.3.0` and left a
  single unambiguous `0.4.0` registration. Downgrade refusal is verified with all nine state
  dimensions unchanged.
- **Secondary `ws.cmd` handling** closed in **P10-A3** (R-21/R-22): preservation across
  upgrade and uninstall, and PATH precedence characterised with fresh-shell confirmation.

The remaining package-level caveat is that the v0.4.0 candidate is **source-bound to commit
`536e019…`**. A later documentation-only commit does not retroactively change the embedded
source SHA. The finally published installer must be rebuilt from the approved post-integration
source commit after the preparation branch is merged.

### 3.2 Disclosable limitations for a narrowly scoped pre-release

These can be disclosed rather than blocking, provided the disclosure is explicit:

- **R-12 reconnect token stability** — an evidence-sufficiency gap about a specific replay, not
  an observed token mismatch.
- **R-13 duplicate-monitor ambiguity** — inherent to single-display test environments.
- **R-15 unreachable-fallback full lifecycle** — partially superseded; the placement behavior
  itself passed under R-14.
- **Secondary-shim PATH precedence** — if a user deliberately places `~\.local\bin` ahead of
  the DevWS `bin` directory, `ws` resolves to that shim. This is Windows command precedence
  behaving as documented, not a DevWS defect; DevWS will not delete or reorder a user's
  unrelated PATH entries to force its own precedence.
- **Upgrade-failure preservation** — not re-exercised in A3; covered by the bootstrapper
  fixture lifecycle in the canonical suite.


### 3.3 Not blockers

- **R-07** is a *historical* verdict retained for accuracy. Publishing v0.4.0 does not require
  the raw predicate to agree with the corrected one; the corrected contract is opt-in and
  documented.

## 4. Product boundary statements

These are release-positioning facts, not aspirations. They must remain true of the published
artifact.

- The visual layout editor ships in the **packaged** installer payload. An ordinary
  **source-layout** installation does not contain `app\editor\DevWS.Editor.exe`.
- **No** automatic live-window reflow, general-purpose tiling, snapping, named zones, monitor
  watching or background daemon.
- **No** MSI/MSIX identity, self-update, attestation or WinGet catalog publication.
- The installer is **unsigned** unless an actual, verifiable signing process is performed.
  Nothing in this release performs or implies signing.
- Configuration schema remains **version 3** and compatible with the established schema-v3
  contract. No new schema version is introduced, and no migration is required.
